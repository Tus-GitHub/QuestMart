# QuestMart

A portfolio/college demo for buying and selling pre-owned physical games. Built with Next.js 15, React 19, Tailwind CSS, PostgreSQL and cookie-based JWT sessions.

## Current milestone

Day 1 foundations are implemented: verified sessions, validated signup/signin, PostgreSQL schema and migrations, isolated local database tooling, catalog failure/retry states, automated tests and CI. Seller listing screens and test checkout are the next milestones; they are **not implemented yet**. RAWG catalog cards are reference game information, not seller inventory.

The former MongoDB integration has been replaced. This creates a fresh database; old MongoDB users/data have not been imported.

## Local setup

Requirements: Node.js 22 and PostgreSQL 17 binaries on PATH (or `POSTGRES_BIN`). On this Windows machine the helper also checks `C:\Program Files\PostgreSQL\17\bin`.

```sh
npm ci
```

Copy `.env.example` to `.env.local` if the latter does not exist. Generate a signing key with `node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"` and put it in `JWT_SECRET`. Do not overwrite an existing local configuration or commit credentials.

```sh
npm run db:local:setup
npm run db:migrate
npm run db:check
npm run check:env
npm run dev
```

Open http://localhost:3000. The database helper creates a separate cluster under `.local/postgres`, binds only to `127.0.0.1:55432`, creates `questmart_demo`, and writes `DATABASE_URL` to `.env.local`. It does not modify installed PostgreSQL services. Generated credentials and data stay in ignored `.local/`; an occupied port or unknown cluster causes a safe failure. The helper does not install PostgreSQL.

```sh
npm run db:local:status
npm run db:local:start
npm run db:local:stop
```

Stopping preserves data. After reboot, start the database before the app. The local cluster owner is for development only; use a dedicated application role for a hosted database.

## Configuration

| Variable | Use |
| --- | --- |
| `DATABASE_URL` | Server-only PostgreSQL connection URL; generated by local setup |
| `JWT_SECRET` | Server-only random secret, at least 32 characters |
| `NEXT_PUBLIC_ROWG_KEY` | Optional RAWG catalog key; this existing public integration is visible to browsers |
| `APP_ORIGIN` | Optional canonical origin when a trusted reverse proxy supplies an internal request URL |
| `TEST_DATABASE_URL` | Explicit opt-in for PostgreSQL integration tests |
| `POSTGRES_BIN` | Optional PostgreSQL 17 binary directory for the local helper |

Do not use `NEXT_PUBLIC_` for database credentials or signing secrets. `.env.prod` is an old ignored file and is not used by this app; configure deployment settings in the host instead.

## Authentication

The browser restores identity through `GET /api/auth/me`, not localStorage. Usernames use 3–30 letters/numbers/underscores/hyphens and are stored lowercase; passwords require 8 characters and a maximum of 72 UTF-8 bytes. Cookies are HttpOnly, SameSite=Lax and Secure in production. Signing key rotation invalidates existing sessions. Mutation routes check origin; SQL queries use parameters.

| Endpoint | Method | Purpose |
| --- | --- | --- |
| `/api/auth/signup` | POST | Validate and create an account |
| `/api/auth/signin` | POST | Set a verified session cookie |
| `/api/auth/me` | GET | Return the authenticated account |
| `/api/auth/signout` | POST | Clear the browser session cookie |

## Database design

`db/migrations/001_initial.sql` defines:

- `users`: UUID identities and unique normalized usernames/emails.
- `listings`: seller-owned physical copies, condition, photos, INR price in integer paise and availability.
- `orders`: buyer/seller relationships, immutable item/price snapshot, separate order/payment statuses, test-only payment mode and one active order per copy.
- `game_prices`: optional reference-price cache, independent of seller prices.

Migrations run atomically under a PostgreSQL advisory lock and record checksums. Never edit an applied migration: add a new numbered SQL file. Order constraints are a foundation, not a checkout implementation. The upcoming order API must authorize users, reserve inventory in a transaction and verify payment-provider events.

## Verification

```sh
npm run lint
npm test
npm run build
```

`npm test` runs unit tests and skips the PostgreSQL integration test unless `TEST_DATABASE_URL` is explicitly set. For local database integration checks without printing credentials:

```sh
node --input-type=module -e "import nextEnv from '@next/env'; import { spawnSync } from 'node:child_process'; nextEnv.loadEnvConfig(process.cwd()); process.exit(spawnSync(process.execPath, ['--test'], { stdio: 'inherit', env: { ...process.env, TEST_DATABASE_URL: process.env.DATABASE_URL } }).status ?? 1)"
```

Integration tests create an isolated schema inside a rolled-back transaction. With the local app running, `npm run test:auth:smoke` checks signup, duplicate accounts, failed login, verified sessions, tampered cookies, cross-origin rejection and logout. It removes only its generated test account. The smoke test is restricted to localhost; set `SMOKE_BASE_URL` for another local port.

GitHub Actions provisions PostgreSQL 17, migrates, lints, tests and builds on pushes and pull requests.

## Hosted deployment

The existing Vercel project is [quest-mart](https://vercel.com/tus-githubs-projects/quest-mart), connected to this repository's `main` branch. Its production address is [quest-mart.vercel.app](https://quest-mart.vercel.app). The project uses the repository root, Node.js 22 and Singapore functions.

PostgreSQL 17 is hosted in [Neon project questmart](https://console.neon.tech/app/projects/dry-dream-46133473), in Singapore. The `production` and `preview` branches are separate databases. Vercel's corresponding environments each have their own pooled `DATABASE_URL` and `JWT_SECRET`; both have `NEXT_PUBLIC_ROWG_KEY`. Database connections verify TLS certificates and use the `questmart_app` role. The migration owner credential is not supplied to the deployed application. Vercel's connection-pool helper releases idle connections before functions suspend.

The initial migration has been applied to both hosted branches. For future schema changes, add a numbered SQL migration, test it against preview first, then apply it to production with an owner **direct** connection. Set `DATABASE_URL` for that migration process only and run `npm run db:migrate`; never replace the Vercel runtime URL with the owner credential or run migrations on every request. Production deploys follow pushes to `main`; other branches use preview credentials. Local `.env.local` remains configured for the local database. No hosted credentials are committed.
